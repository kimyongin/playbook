# 업무에 맞는 개발 방식 고르기

개발 방법은 사용 범위, 사용 방식, 인증·권한, 자료 출처를 조합해 선택한다. 참여자의 업무에 관계있는 선택부터 설명한다.

## 개인 작업과 공동 서비스

| 방식 | 장점 | 부담과 한계 |
| --- | --- | --- |
| 내 컴퓨터에서 에이전트·플러그인으로 작업 | 별도 앱 없이 개인 업무를 빠르게 자동화 | 다른 사람도 같은 기능을 자기 계정으로 쓰려면 별도 환경과 공유 규칙이 필요 |
| 서버에 배포하는 공동 서비스 | 같은 자료와 기능을 여러 사람이 각자의 계정으로 사용 | 로그인·권한·운영 비용·장애 대응을 고려해야 함 |

로컬 에이전트로 공동 서비스를 개발할 수도 있다. 서버 배포에는 관리형 서비스나 서버 함수를 활용하는 방법도 있다.

## 화면과 대화

| 사용 방식 | 어떤 경험인가 | 장점과 부담 |
| --- | --- | --- |
| 웹 화면 | 목록·입력창·버튼을 직접 조작 | 상태를 눈으로 확인하고 정밀하게 다루기 좋음. 화면과 사용 흐름을 설계해야 함 |
| 에이전트에게 자연어로 요청 | 에이전트가 MCP 업무 도구를 호출하고 결과를 설명 | 원하는 결과를 말로 요청하고 다른 도구와 함께 활용 가능. 요청 해석·도구 설계·계정 연결·클라이언트 지원을 고려해야 함 |

HTTP API는 프로그램이 서버에 요청하는 창구다. 웹은 보통 HTTPS로 API를 사용하고, 원격 MCP도 HTTPS를 사용할 수 있다. MCP는 에이전트가 제공된 도구를 발견하고 호출하는 규약이다. 웹과 에이전트는 같은 업무를 사용하는 두 인터페이스로 함께 제공할 수 있다.

## 인증과 권한

인증은 “누구인가”, 권한은 “무엇을 보거나 바꿀 수 있는가”다.

| 방법 | 장점 | 직접 맡을 부분 |
| --- | --- | --- |
| 계정 시스템 직접 구현 | 특수한 요구에 맞추기 쉬움 | 비밀번호 보호·로그인·복구·권한과 지속적인 보안 관리 |
| 기존 계정 제공자 연결 | 회사·소셜 계정을 활용하고 비밀번호 관리 부담을 줄임 | 로그인 연동과 앱의 사용자·업무 권한 |
| Supabase 같은 관리형 기반 | 인증·저장·접근 제어 기반을 함께 사용 | 제공자 설정, 업무별 권한 정책, 서비스 제약과 비용 |

이 방법들은 조합할 수 있다. Supabase에서도 기존 계정으로 로그인할 수 있다. OAuth는 접근을 위임하는 표준이며, 로그인에는 OIDC 같은 사용자 확인 방식이 함께 쓰인다. 참여자에게는 “내 계정으로 로그인”과 “에이전트에게 대신 할 일을 허용”하는 경험으로 설명한다.

## 자료 확보

| 방법 | 장점 | 부담과 한계 |
| --- | --- | --- |
| 직접 입력·파일 업로드 | 연동 없이 작은 기능부터 시작 | 입력 부담·오타·중복 처리 |
| 외부 API | 구조화된 정보를 반복해서 가져오기 쉬움 | 제공 범위·인증·호출 제한·비용 |
| 웹 수집 | API가 없는 자료에도 접근 가능 | 페이지 변경, 접근·이용 조건, 유지보수 |

자료 출처는 섞어 쓸 수 있다. 업무에 필요한 갱신 주기와 실패 시 처리를 함께 정한다.

## 공동 업무 앱의 선택

**공동 서비스 + 웹·자연어 에이전트 인터페이스 + Supabase 인증·권한·저장**을 기본으로 한다. 자료 출처는 업무에 맞게 선택한다. 예를 들어 팀 요청은 직접 입력으로 시작하고, 이후 필요한 외부 자료를 연결할 수 있다.

이 조합은 동료와의 공동 사용과 에이전트 활용을 함께 경험하게 한다. 그만큼 웹 외에도 업무용 MCP, 사용자 동의, 서버 권한, 배포를 구현·검증해야 한다. 참여자가 다른 조합을 택하면 그에 맞춰 스킬 범위를 조정한다.
